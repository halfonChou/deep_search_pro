## 模块一：Server.py（后端入口）

---

### 1.1 这个文件是干什么的

`api/server.py` 是整个项目的**后端入口**，基于 FastAPI 框架构建。它负责接收前端请求、调度 Agent 后台运行、管理文件上传下载、并通过 WebSocket 实时推送 Agent 执行进度。

### 1.2 技术框架

- **FastAPI**：Python 异步 Web 框架，自动生成 Swagger 文档，原生支持 async/await
- **Uvicorn**：ASGI 服务器，负责启动和运行 FastAPI 应用
- **asyncio**：Python 异步库，提供事件循环、create_task 等异步原语
- **WebSocket**：双向长连接协议，用于实时推送 Agent 进度
- **Pydantic**：数据验证库，用 BaseModel 定义请求体结构

### 1.3 数据流动全景

```
服务启动
  └─ 创建事件循环 loop → 交给 WebSocket 管理器保存

用户操作（按时间顺序）：
  1. POST /api/task      → 生成 thread_id → 后台启动 Agent → 立即返回 id
  2. WS /ws/{thread_id}  → 建立长连接 → Agent 实时推进度
  3. POST /api/upload     → 带 thread_id 上传文件 → 存到 session 目录
  4. Agent 运行完毕       → 结果写入 output 目录
  5. GET /api/files       → 查看 output 下的文件列表
  6. GET /api/download    → 下载指定文件

thread_id 是贯穿全程的纽带，把所有接口串在一起。
```

### 1.4 关键知识点速查

| 概念 | 说明 |
|------|------|
| `await` | 当前函数暂停等待，事件循环去忙别的，回来后继续 |
| `create_task` | 扔到后台不等，当前函数直接往下走 |
| `resolve()` | 把相对路径转成绝对路径，展开 `..` |
| `is_relative_to()` | 判断路径是否在某个目录下 |
| `rglob("*")` | 递归遍历目录下所有文件（含子目录） |
| `stat()` | 获取文件元信息（大小、修改时间等） |
| `FileResponse` | 把服务器文件作为响应发给客户端，触发下载 |
| `Path(...)` | 把字符串转成路径对象，才能调用路径相关方法 |
| `mkdir(parents=True, exist_ok=True)` | 创建目录，自动建父目录，已存在不报错 |

### 1.5 FastAPI 参数来源规则

| 来源 | 判断条件 | 示例 |
|------|----------|------|
| 路径参数 | 参数名出现在路由的 `{}` 里 | `@app.get("/ws/{thread_id}")` |
| 查询参数 | 参数名不在路由里，无特殊标注 | `@app.get("/api/download")` → `?path=xxx` |
| 请求体 | 用 `Body()`、`File()`、`Form()` 标注 | `files: List[UploadFile] = File(...)` |

### 1.6 面试 Q&A

**Q1：CORS 是解决什么问题的？不加会怎样？**

CORS（跨域资源共享）是**浏览器的安全策略**。当前端页面域名（如 `localhost:3000`）和 API 域名（如 `localhost:8000`）不同时，浏览器会拦截请求。不加 CORS 中间件 = 服务端没有在响应头里声明"我允许谁来访问" = 浏览器默认拒绝。注意：Postman、curl、后端服务器调 API 完全不受影响，因为 CORS 是浏览器自己加的规则，不是 HTTP 协议的规则。中间件加在**服务端**，作用是在响应头里加上 `Access-Control-Allow-Origin` 字段，浏览器看到这个字段才放行。`allow_origins=["*"]` 表示允许所有域名访问，生产环境应改为具体域名。

**Q2：为什么用 get_running_loop() 而不是 new_event_loop()？**

因为 uvicorn 启动时已经创建了一个事件循环（循环 A），所有路由、WebSocket 都跑在这个循环里。如果用 `new_event_loop()` 创建一个新循环（循环 B），它和循环 A 完全隔离。把循环 B 交给 WebSocket 管理器，后台线程往 B 里投递消息，但 WebSocket 连接在 A 里，消息永远送不到。`get_running_loop()` 拿的就是 uvicorn 正在用的那个循环，确保所有东西在同一个循环里。

**Q3：create_task 创建的后台任务报错了，前端能收到吗？**

**不能。** 错误会被静默吞掉，控制台只会打一个 warning。因为 `create_task` 扔到后台就不管了，没人 `await` 它，也就没人接住异常。解决方案：在 `run_deep_agent` 内部自己 try/except，出错时通过 WebSocket 主动推一条错误消息给前端：

```python
async def run_deep_agent(query, thread_id):
    try:
        # 正常逻辑...
    except Exception as e:
        await manager.send(thread_id, {"type": "error", "message": str(e)})
```

**Q4：上传接口为什么用 File(...) 和 Form(...)，不能都用 JSON？**

JSON 根本**不能携带二进制数据**。JSON 只能装文本（字符串、数字、布尔值），图片、PDF 是二进制数据，塞不进去。传文件必须用 `multipart/form-data` 格式（HTTP 规范决定的）。在这种格式下，所有字段都是表单字段，所以 `thread_id` 也只能用 `Form(...)` 接收。

**Q5：下载接口的路径安全检查在防什么？攻击者怎么攻击？**

防止**路径穿越攻击（Path Traversal）**。攻击者在 path 参数里用 `..` 往上跳目录：`GET /api/download?path=output/../../etc/passwd`。防御方式：`resolve()` 把 `..` 展开成真实路径，`is_relative_to()` 检查展开后是否还在 output 目录下，不在就拒绝。

**Q6：WebSocket 的 while True 循环会不会占满 CPU？**

**不会。** `await` 让函数暂停，交出控制权给事件循环，不消耗 CPU。`while True` + `await` = 等待不耗 CPU。`while True` 不带 `await` = 死循环烧 CPU。

**Q7：shutil.copyfileobj 和 file.read() 有什么区别？**

`file.read()` 一次性把整个文件读进内存，大文件会撑爆内存。`shutil.copyfileobj` 流式复制，每次只搬 16KB，内存占用恒定。

## 模块五：Context.py（协程上下文隔离）

---

### 5.1 这个文件是干什么的

`context.py` 解决的核心问题是：**多个用户同时使用 Agent 服务时，保证数据不串台**。它提供协程级别的变量隔离，让每个用户请求在整个调用链中都能正确识别"我在服务谁"。

### 5.2 为什么需要 ContextVar

在 asyncio 异步环境中，所有协程跑在同一个线程里。普通的全局变量和 threading.local 都无法隔离不同协程的数据：

| 方案 | 隔离级别 | asyncio 下能用吗 | 原因 |
|------|----------|-----------------|------|
| 全局变量 | 无隔离 | ❌ | 协程 B 会覆盖协程 A 设的值 |
| threading.local | 线程级 | ❌ | 所有协程在同一线程，它认为是"同一个人" |
| ContextVar | 协程级 | ✅ | 每个协程各一份独立数据 |

### 5.3 数据流动

```
请求进入
  │
  ▼
set_session_context("sessions/aaa/")  → 返回 session_token
set_thread_context("aaa")             → 返回 thread_token
  │
  ▼
asyncio.create_task(run_deep_agent)   → 子协程自动复制父协程的 context
  │
  ▼
Agent 调用链（任意深度）
  ├─ 搜索景点 → get_thread_context() → "aaa"
  ├─ 规划路线 → get_session_context() → "sessions/aaa/"
  ├─ 推送 WebSocket → get_thread_context() → "aaa"
  └─ 保存文件 → get_session_context() → "sessions/aaa/"
  │
  ▼
请求结束
  └─ reset_session_context(session_token, thread_token)  → 恢复原值，防止数据污染
```

### 2.4 两个 ContextVar 变量

| 变量 | 存什么 | 用途 |
|------|--------|------|
| `_session_dir_ctx` | 文件目录路径，如 `"sessions/aaa/"` | 知道文件存在哪，读写文件用 |
| `_thread_id_ctx` | 会话 ID，如 `"aaa"` | 知道服务的是谁，推 WebSocket 消息用 |

### 2.5 ContextVar 对象方法（只有 3 个）

| 方法 | 作用 |
|------|------|
| `.set(value)` | 给当前协程设值，返回 token（记录旧值的凭证） |
| `.get()` | 取当前协程的值，没 set 过就返回 default |
| `.reset(token)` | 用 token 恢复成 set 之前的值 |

### 2.6 隔离原理

不是"过滤"其他协程的值，而是**切换**。每个协程自带一个 Context 字典，事件循环切换协程时，整个 context 环境跟着切换：

```
事件循环：
├─ 切到协程A → context_A.run(A的代码) → get() 查 context_A → "aaa"
├─ 切到协程B → context_B.run(B的代码) → get() 查 context_B → "bbb"
└─ 切回协程A → context_A.run(A的代码) → get() 还是 context_A → "aaa"
```

`create_task` 创建子协程时会**复制**父协程的 context（不是共享），子协程修改不影响父协程。

### 2.7 面试 Q&A

**Q1：ContextVar 和全局变量的核心区别是什么？**

全局变量在 asyncio 异步环境中无法隔离不同协程的数据。前一个协程设的值会被后一个协程覆盖，导致数据串台。ContextVar 是协程级隔离，每个协程有自己独立的一份数据。

**Q2：为什么不用 threading.local 而用 ContextVar？**

因为 asyncio 所有协程跑在同一个线程里。`threading.local` 只做到线程级隔离，同一线程里的协程它全当成"同一个人"，无法隔离。`ContextVar` 是协程级隔离，专门为异步编程设计。

**Q3：.set() 返回的 token 是干什么用的？不调 reset 会怎样？**

token 是 `.set()` 之前旧值的凭证，用于恢复原状。不调 `reset` 的后果：值一直留在当前 context 里。如果这个协程的 context 被复制给了新协程（`create_task` 时），新协程会继承到遗留的脏数据，导致**数据污染**——比如用户 B 的协程里残留着用户 A 的 thread_id。

**Q4：get_thread_context() 不用传参，任意深层直接调。好处和坏处？**

**好处**：代码简洁，不管调用链多深都直接 `get_thread_context()` 拿到值，不用每个函数都加 `thread_id` 参数。**坏处**：隐式依赖。看函数签名看不出它依赖 thread_id，必须读内部代码才知道。如果忘了提前 `set`，运行时才发现拿到的是 None。

**Q5：create_task 创建的子协程能拿到父协程 set 的值吗？**

**能。** `create_task` 创建子协程时会复制父协程的 context。这样 Agent 在子协程里直接 `get` 就能拿到 thread_id，不用传参。复制不是共享——子协程修改自己的值不影响父协程，就像复印件和原件互不干扰。
